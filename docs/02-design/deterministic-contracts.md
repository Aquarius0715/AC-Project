# Deterministic Contracts for Phase 1A Implementation and Verification

Demo design defined under DEC-11. Demo scope and business policy were adopted in [DEC-12](../00-prepare/internal/decision-record-2026-09-16.md). Independent G1 checks technical consistency. This is not commercial approval or production API design. It makes existing DD summaries concrete. For each FR, use role documents for actors, the relevant DD for starting conditions/inputs/processing/success, operation-catalog authorization columns for permissions, D01 here for failures, and the screen catalog for UI states. Together these form one contract. Implementers must not add undefined business conditions. Adapter replacement alone does not guarantee future external API integration.

## D01 Authorization and Failure Order

Calls are read=`operation(context,input,{signal?})`, write=`operation(context,input,writeOptions)`. Success returns ServiceResult; failure rejects with DomainError. Public login/reset-preview and demo controls are explicit exceptions. Do not grant all business operations based on role alone.

Check in this order. If input has multiple errors, return the first one.

1. Invalid input structure, type, length, or enum: VALIDATION. Reject unknown fields.
2. No session or expiresAt <= now: UNAUTHENTICATED.
3. ID missing, in another tenant, or outside customer/contractor scope: NOT_FOUND. Do not disclose existence.
4. Read scope exists but action permission is missing, assignment is outside its period, qualification expired, self-approval attempted, or contract restriction violated: FORBIDDEN.
5. After authorization, look up the idempotency key. Same content returns existing result; different content returns CONFLICT.
6. expectedVersion mismatch, invalid state, confirmed schedule overlap, or active-operation conflict: CONFLICT.
7. Related-value inconsistency (units, same customer, delegation-period containment, required reason, model options): VALIDATION.
8. Control target is offline: OFFLINE. Do not change state. D03 defines restriction-only undelivered intents.

Do not return stored results after permission expiry. FORBIDDEN makes zero business changes and one masked denial audit. Deduplicate identical denied requests by correlation ID into one audit. Successful reads add no audit.

Treat an entire DTO with an unknown enum as UNAVAILABLE; show neither raw source text nor internal exceptions. Invalid URL resource IDs show not-found. Invalid filters/dates/enums show VALIDATION correction without resetting inputs. Unknown routes show not-found. Out-of-scope IDs on known routes use the same not-found text. Show network failures separately from device offline.

## D02 Trigger Arbitration and Actors

Automation/Policy carries ownerMembershipId, createdByUserId, and version. Actor is the owner at creation, not the current viewing role. Editing does not change owner. Expired owners cause suppression.

`automations.simulate/fire` takes `{eventId, occurredAt, unitIds, facts, phase}`. phase is schedule_start/schedule_end/condition. No path that specifies an individual rule ID may bypass other policies. facts contain per-unit metric/value/unit/observedAt/quality and typed arrival/departure/occupied/peak values. Each event evaluates all active tenant Policies/Automations against one snapshot. Authorize each rule using its saved owner. Notification evaluation and Command-candidate arbitration return separate results under SR21. phase classifies the trigger, not which rules to evaluate. Enumerate all scheduled start/end Actions due at occurredAt; evaluate condition rules using merged facts and that snapshot. Multiple phases in one tick reference one arbitration result. UI callers also need read/trigger permissions for all target units: out-of-scope returns NOT_FOUND, missing permission FORBIDDEN. Nonmatching conditions in an authorized evaluation return suppressed. Internal demo-clock evaluation reauthorizes each owner without a viewing session. Do not expose the internal evaluator to UI.

Arbitrate Commands per unit: only one even for different Actions. alert and notify_only policies do not compete for Commands. Filter candidates by capabilities, restrictions, owner permissions, consent, fresh input, and enabled. Choose one in HQ-policy then customer-automation order; within a level use descending priority, then ascending ASCII ID. Pass only the winner to Command policy. Evaluate and accept Commands in one memory transition so caller order cannot let customers outrank HQ. Merge events sharing occurredAt into one tick batch. For competing facts of the same metric, use the last eventId in ASCII ascending order. Schedule simultaneous scenario events with demo.trigger and finalize together through demo.advanceClock. UI fire combines all current-tick facts in one request for immediate evaluation. A later fire with different facts or an extra different phase for the same tenant/occurredAt returns CONFLICT without reevaluation. If scheduled and immediate triggers share a tick, merge all scheduled events first. Per-event results reference the same tick result; never recreate Commands.

FireResult/SimulationResult follow canonical DTOs, sorted by unitId ascending. Simulated control results use decision=selected/suppressed and create no Commands. Both results also return independent notifications arrays (canonical DTO/SR21). Partial multi-unit failure does not cancel other units' requests. Duplicate unitIds return VALIDATION. At most one Command per tick/unit. Repeating tenant/eventId/phase returns existing results even with another key; reusing eventId with different facts returns CONFLICT.

Clock triggers for schedules/patterns use IR54 internal evaluation; pattern matching follows IR52. Scheduled ending is a separate Action. Suppress future events after disable/consent withdrawal; do not label past Commands cancelled. Pending manual control suppresses automation as busy, without later automatic resend. The next valid trigger may change confirmed manual settings.

## D03 Per-Unit Restriction Recovery

Restriction state allows only scheduled/requested/applied/release_requested/released/cancelled. exception is an `{until,reason}` attribute, not a state. Grace/exception release requests do not change invoices. Do not reapply automatically after expiry; reevaluate through a new notice.

On application, create one Command record per unit. Only restriction Commands for offline devices keep a delivery intent with status=requested and delivery=not_sent. Normal commands.create creates zero Commands offline. Never display applied without confirmation. Intent expires after 30 seconds, retaining definitive non-delivery evidence. Reconnection alone does not deliver it automatically.

perUnit[].applyState is `not_sent|sent_unknown|applied|not_applied`; perUnit[].releaseState is `none|waiting_reconcile|requested|released|not_required|failed`. Required data: unitId, applyCommandIds, releaseCommandIds, observedRestriction, observedAt, evidenceId, pendingReason. Use only observations from current generation and latest device sequence.

| Apply state | Full payment / override / grace or exception after application | Next action and completion criteria |
|---|---|---|
| not_sent | Finalize undelivered apply as cancelled; perUnit[].applyState=not_applied | Zero-delivery evidence gives release=not_required, even offline |
| not_applied | Apply-rejection evidence exists | release=not_required; create zero remove Commands |
| sent_unknown | release=waiting_reconcile; keep restriction policy | Fetch current observation with restrictions.reconcile; remain pending if offline or observation is old |
| applied | If online, create remove and set release=requested | released requires matching ID/rulesVersion, successful Command, and observedRestriction=null |
| sent_unknown→observation null | Successful reconcile with fresh non-application evidence | release=not_required |
| sent_unknown→observation present | Successful reconcile | Send remove. A different Restriction ID returns CONFLICT for manual checking |
| remove failed/expired | release=failed; keep aggregate release_requested | Explicit retry creates a new Command; keep the old one in history |

`restrictions.retry({restrictionId,unitIds,phase:apply|release,confirmedRulesVersion})` requires latest version, new key, and reason. apply requires requested and not_sent/confirmed failure; recheck unpaid status, no grace, same notice version, and online. sent_unknown requires reconcile first. release requires release intent, reconciled or applied status, and no unfinished remove. For already successful units, return existing results without resending. Return per-target-unit results. Do not replace unresolved apply with a new apply.

`restrictions.reconcile({restrictionId,unitIds})` queries simulated observation events and is a write because it stores successful evidence. Observations older than 30 seconds cause TIMEOUT. When all perUnit[].releaseState are released/not_required, aggregate state is released. Late acknowledgements after an apply request do not restore aggregate applied; reconcile observations and decide whether remove is needed. Record contradictory observations after released/cancelled in separate SR26 recoveryCases; do not reactivate terminal Restrictions. Never invent device success.

## D04 Idempotency, Payments, and Waiting

IR35 is authoritative for release triggers (payment confirmation, grace/exception, override, explicit release) and `restrictions.release` prerequisites/idempotency.

Every write key is UUID, scoped by generation/tenantId/userId/operation. Normalize structured payloads by key order for comparison, retaining the original expectedVersion. Resend the same intent with the original payload. Keep keys/results until reset, through role switches and logout. Reauthorize before returning. Return the same Promise while pending, original result after success, or same failure after a final business failure. Transport TIMEOUT/UNAVAILABLE does not finalize business outcomes.

Even without a resource ID, `writes.getResult({operation,idempotencyKey})` returns `not_received|pending|succeeded|failed`, resource ID, and original result/error. Return only for the creation userId and currently permitted target scope. If unconfirmed, show resend using the same key/payload. A new intent after final failed uses a new key. Never reuse an old key for a new payment attempt.

Payment initiate takes invoiceId/method/demoConfirmed; returned Payment.id is the attempt ID. Later `payments.simulate` requires `{event:processing|confirm|fail,paymentId,eventId,paymentReference}` and updates only that attempt. confirm requires processing; fail requires initiated/processing. Same eventId returns existing result. Late confirm after terminal failed returns CONFLICT, as does fail after confirmed. References are unique within tenant. After authorization, repeated confirmation of the same invoice/reference/amount returns existing success. Reuse on another invoice returns CONFLICT. demo_instructions is a separate union branch returning NotificationPreview without creating Payment. Provide no card-number input, even for fixed numbers.

Transport wait is 10 seconds per attempt. Inject transport faults (UNAVAILABLE/TIMEOUT/RATE_LIMITED/DELAY) and network loss through IR37 demo.trigger. Only read UNAVAILABLE retries automatically: at most two extra attempts after 1 and 2 seconds (33 seconds overall maximum). No automatic retry for TIMEOUT/VALIDATION/authorization errors or writes. RATE_LIMITED accepts integer 1–3600 seconds; invalid/omitted means 30 seconds. Disable same-operation buttons and service acceptance during this period, showing remaining seconds. Reset/role change cancels viewing waits but does not roll back accepted business work.

Command acknowledgement requires receivedAt < expiresAt. At now==expiresAt, process expiry first. Event order: reset → permission change → expiry → device response → periodic evaluation → screen subscription notification. Late acknowledgement adds only history and new observations; never change expired to acknowledged. Demo clock controls timers.

## D05 Device Mutual Exclusion, Registration, and Retirement

Per unit, enforce mutual exclusion among Command(requested/sent), DiagnosticRun(awaiting_start/running/end_requested), and DeviceOperation(queued/running). Only a run's own start/end Commands share its reserved slot. check/calibrate/FW and normal Commands reject each other as CONFLICT. FW/check moves queued→running→succeeded/failed and becomes failed/TIMEOUT 60 seconds after creation. At the exact boundary, failure wins. Late success records history only; do not update firmwareVersion. Retry uses new operationId/key. Calibration uses the same exclusion check, immediately appends history, and leaves measurements unchanged.

devices.register takes unitId and jobId (required only for technicians), reserving targetUnitId. unitId remains null until bind. Only the creator Membership and HQ with device.manage can read unbound devices. Validate assignment at registration. Each Unit has at most one active Device; each Device has one Sensor per metric. Reject duplicate metrics in phase 1A. Normalized serial uniqueness is tenant-wide. bind checks both unit scopes, reason, exclusion, no unresolved tamper, and no active restriction/recovery case under SR24. Keep old binding with its end time; never rewrite Telemetry/Alert/Command.unitId. New bindings get new sensorIds. Keep event-time binding/Unit/customer and authorize each history row under SR24.

Connection is unknown/connecting/online/offline/error (ACUnit derives it from Device under IR47; operation start follows IR67). Running check sets connecting, success online, explicit connection failure error, and communication loss offline. FW failure is an operation error and must not change connection arbitrarily. powerSignal unknown/on/off and tamper clear/detected are separate. Show tamper warnings, operation failures, connection, and last-known power together. Never color unknown values as normal.

Follow IR39 for excluding archived resources from lists/summaries/candidates and projecting individual reads. units.archive returns CONFLICT with active Job, active Device binding, active Restriction/Command/run/operation, or unexpired Contract; history alone is allowed. Disable active Automations in the same transition with reason unit_archived. No new actions after archive; audit/completed reports remain visible under original scope. units.delete physically deletes only unused Units with zero references; history references cause CONFLICT. Property/Space cannot archive while any descendant Space/Unit remains. Customer deactivation also conflicts with active Unit/Contract/Job. Relocation within one customer keeps ID and increments version by 1. IR02 prohibits customer changes for existing IDs and cross-tenant transfers.

## D07 Sensors, Subscriptions, and Numbers

Telemetry series key is tenantId/unitId/sensorId/metric. sensorId is required; inspections use inspection-item ID. Metric/unit mappings and phase 1A synthetic ranges: temperature/°C:[-50,100], humidity/%:[0,100], co2/ppm:[0,10000], pm25/µg/m³:[0,1000], power/kW:[0,100], vibration/mm/s:[0,100], refrigerant_pressure/kPa:[0,5000]. These are not real capabilities or health standards. Normalize nonfinite values to value=null/quality=suspect before DTO; keep suspect, not missing. Under IR12 RawMeasurement normalization, out-of-range values, unknown units, observedAt>receivedAt, or receivedAt>now become suspect and are excluded from summaries/control. Input null is missing, except null with an IR12 quality cause stays suspect. Otherwise quality priority is missing→suspect→stale→valid. Stale means now-observedAt>120 seconds (use sensor's positive-integer staleAfterSeconds). suspect/missing/stale may display last value and quality but cannot support normality checks/automatic triggers. Historical integration uses samples valid at observation time; becoming stale now does not remove past totals.

`events.subscribe(context,{afterCursor,resources,unitIds},listener)` is a Repository support interface returning unsubscribe, separate from the Promise operation catalog. Events are `{generation,cursor,eventId,entityType,entityId,version,occurredAt,changedFields}`. cursor increases across all events within a generation; eventId is unique. Read meta returns eventCursor. Fetch a snapshot, subscribe from its cursor, and replay intervening events. Keep all history until reset. For out-of-scope events, notify only cursor advancement. Gaps require fresh snapshot then resubscribe. Ignore duplicate cursors/older entity versions. Unsubscribe on role changes; reject all old events on generation change. Reconnection starts with a fresh snapshot; old heartbeats must not restore online. Clock ticks notify stale/expiry reevaluation even without new data.

All Page reads accept cursor/limit, default 25 and maximum 100. cursor binds normalized query conditions, scopeVersion, snapshotVersion, and offset. Changed conditions return VALIDATION; business updates do not change the snapshot being read (SR14). Expired cursors return CONFLICT. Final sort tie-break is always id asc. Notifications sort severity critical→warning→normal, occurredAt desc, id asc. Job UI sorts severity/dueAt/status asc/desc. Telemetry sorts observedAt asc, sensorId asc, id asc. Fetch 1000 telemetry points in 10 pages of 100; missing pages must not look like a complete healthy chart.

KPIs use dedicated summaries.get over all search targets, not the current page. Match kind=customer/partner/technician to role. Exclude out-of-scope items from counts. Partner offer/active/review/overdue counts are offered, accepted+assigned+in_progress, submitted, and incomplete with dueAt<now. Technician counts are distinct assigned Units, assigned jobs, and incomplete overdue jobs. Customer/admin power classifications share SR27 effectivePowerState. Customer also returns open/acknowledged Alerts with severity=critical/warning (IR51). Required latest telemetry missing means unknown (C01 conditions). admin.summary billing values require billing.manage; otherwise amountsByCurrency=null and billingVisibility=forbidden, not 0.

members.capacity returns minutes in the intersection of available work intervals for date (seed: 09:00–17:00 Asia/Kuala_Lumpur; holidays empty) and the union of assignment intervals. A zero/undefined denominator gives null. Count only confirmed assignments in the numerator. 4h/8h=50.0%.

Energy uses fixed 60-second slots. [from,to) must align to UTC minute boundaries, at most 366 days; partial boundary minutes return VALIDATION. Use only the power sample at slot start for a 60-second rectangular integral, without interpolation or carry-forward. Exclude missing/suspect. Expected count=target unit count×minutes; coverage=valid slots/expected count. All missing gives kWh/cost/emissions null and coverage=0. Zero targets gives expected count=0 and coverage=null. For duplicate slot-start samples, choose maximum device sequence, then first ASCII-ascending ID for ties, before checking IR08/IR11 origin/quality/boundary. Do not substitute later within-slot samples.

Cost is slot kWh×tariff at slot start, summed then rounded to minor units. Tariffs use nonoverlapping half-open intervals. A missing slot tariff gives null slot cost and null total cost; energy may still display. The fictional tariff is fixed 0.5 MYR/kWh, excluding taxes/fixed charges. Use decimal rational arithmetic, not rounded display values. Display energy to 1 decimal, money to 2, percentages to 1. reduction=baseline−actual; if separately showing change, name it deltaKWh=actual−baseline. Baseline 0 gives null reduction rate. Compare only matching unit sets, boundaries, and minute counts, with actual coverage=100% and an SR29-comparable baseline. Measured baselines require coverage=100%; fixed assumed baselines must be labeled modeled. Partial coverage may show actuals but comparison differences/rates are null. MRV saves factor-version snapshots; coverage<100% sets incomplete=true and remains draft, not demo_reviewed. 100 kWh/80 kWh/0.5 MYR/0.5 kgCO₂e gives reduction 20 kWh, 20%, savings 10 MYR, emissions 40 kgCO₂e.

## D12 Shared Field, Support-Read, and Edit-Version Rules

Canonical DTOs/inputs/results are in service-contracts.ts; operation-specific lengths/numbers are in each DD field table. IDs follow DDC-01; normalize Instants to UTC millisecond precision; Version is a positive integer. Unknown input fields return VALIDATION. Do not omit DTO nulls. Unspecified name fields allow 1–120 characters. All reason fields (reason/cancelReason/declineReason/changeReason/resolutionReason/reviewComment/purpose) require 1–1000 trimmed Unicode code points regardless of DD text (IR87). ID arrays contain 1–100 unique items. Allow meaningful empty arrays for report.items/parts/measurements/attachments, permissions/scopes, and query unitIds. Normalize free-text newlines to LF and never execute HTML. Unsafe-integer money/nonfinite numbers return VALIDATION. Check lengths after normalization.

## D16 Revisiting and Generating Recurring Maintenance Plans
