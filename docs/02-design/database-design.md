# Database Design (Aurora PostgreSQL)

## 1. Purpose and scope

This document designs the production relational database for the Go backend ([backend Go design](backend-go-design.md), [backend architecture](backend-architecture.md)). The executable schema is [db/schema.sql](db/schema.sql) (99 tables including default partitions as of 2026-10-08, 38 permission rows). It was applied to PostgreSQL 16 on 2026-10-07 and checked for tenant isolation (RLS), the append-only audit trigger, and the no-overlap assignment constraint. Status `PROPOSED` (IR118, DEC-69).

The source of truth for fields and states is [service-contracts.ts](service-contracts.ts); this document says how each type is stored. Phase 1A still uses the in-browser mock and does not use this schema.

| notify | Notifications | notifications, deliveries, templates, ref_* reference copies of other domains' rows kept from RowChanged events (IR188) |
| audit | Audit | audit_log (append-only, partitioned) |

Rules:

1. A module reads and writes only its own schema. References to another module's rows are plain `uuid` columns **without** foreign keys (for example `assets.units.model_id` → devices capability); consistency across modules is kept by the owning module's interface and by events.
2. Foreign keys inside a schema include `tenant_id` (`FOREIGN KEY (tenant_id, x_id) REFERENCES … (tenant_id, id)`) so a row can never point into another tenant.
3. `identity.users` is global (one person may hold memberships in several tenants); everything else is tenant-scoped.

## 3. Conventions

| Topic | Convention |
|---|---|
| Keys | `id uuid` primary key, UUIDv7 generated by the application (time-ordered). Versioned documents use `(id, version)` as the key. |
| Common columns | `tenant_id`, `version int` (optimistic concurrency, starts at 1), `created_at`, `updated_at` (`timestamptz`, UTC; defaults use `platform.app_now()`, the transaction's business clock, IR157). |
| Enumerations | `text` + `CHECK (… IN (…))`, matching the TypeScript unions; adding a value is a migration that replaces the CHECK. |
| Money | `amount_minor bigint` + `currency char(3)` (`MYR`, `USD`); no floating point; no conversion between currencies. |
| Time ranges | `tstzrange` for slots, terms and periods (`[start, end)`), `daterange` for unavailability days; overlap rules use GiST exclusion constraints. |
| Value objects | `jsonb` when always read and written whole (observed state, report items, costs, rating, policy definitions); a column or child table when filtered, joined, or updated alone. |
| ID arrays in TypeScript | Become join tables when queried in both directions (unit ↔ alert policy, contract ↔ unit, restriction ↔ invoice / unit, automation ↔ unit, job ↔ alert); stay `uuid[]` when only displayed (evidence IDs, created IDs of an import). |
| Names | Lower snake case; tables plural; indexes `<table>_<purpose>`. |
| Fixture IDs | Seeded rows from `fixture-contract.json` use deterministic UUIDv5 keys: `uuid.NewSHA1(6f1c3a52-6d0b-5c1e-9a57-0d1b7a4c2e10, fixtureId)` (backend `internal/seed`). Tests and the web demo compute a row's ID from its fixture ID (for example `unit-online-rto`); application-created rows keep UUIDv7. |
| Soft delete | `archived boolean` for assets (history must stay readable, IR39); hard deletes only where the contract allows (`units.delete` when not in use). |

## 4. Entity relationships (per schema)

```text
identity:  organizations 1─* memberships *─1 users
           memberships 1─* membership_permissions *─1 permissions
           memberships 1─* membership_scopes · 1─* qualification_grants · 1─* consents
assets:    customers(1 organization) · properties 1─* spaces (self-parent) · properties 1─* units
           units 1─* unit_alert_policies
devices:   capabilities(id,version) · devices 1─* sensors · devices 1─* device_bindings (one active)
           devices 1─* device_operations · 1─* device_events 1─* device_event_notes · firmware_campaigns *─* devices
control:   commands · diagnostic_runs → commands(start/end) · automations *─* units · automation_policies *─* units
           automation_runs → commands
monitoring: alert_policies 1─* default_rule_settings · alerts → previous alert · measurements → aggregates
maintenance: plans 1─* jobs · jobs 1─* offers 1─* partner_slot_proposals · jobs 1─* slot_proposals
           jobs 1─* assignments (one active) · jobs 1─* work_reports(id,version) 1─1 report_reviews
           jobs 1─* attachments · job_notes · job_events · jobs → follow_up_of_job_id
billing:   contracts(id,version) 1─* contract_units · contracts 1─* invoices 1─* payments · stripe_events → payments
           payout_statements 1─* payout_lines · 1─* payout_queries
restrictions: restrictions 1─* restriction_invoices · 1─* restriction_units
energy:    baselines(id,version) · emission_factors(id,version) · mrv_reports(id,version) 1─* mrv_reviews
           offset_quotes 1─* offset_records 1─* offset_attempts
notify:    notifications 1─* deliveries · templates
```

Cross-schema references without foreign keys (logical only): units → capability, commands → unit / device / job / restriction, jobs → unit / alert / contractor organization, invoices → customer, restrictions → contract / invoice / unit, notifications → membership, audit → any target.

## 5. Constraints that encode business rules

| Rule | Constraint |
|---|---|
| External technician needs an end date (FR-A03) | CHECK on `identity.memberships` |
| Client memberships carry a client role; others do not | CHECK `(role = 'client') = (client_role IS NOT NULL)` |
| One active device binding per device and per unit | Partial unique indexes on `devices.device_bindings` where `unbound_at IS NULL` |
| Duplicate serial (AT-T11-E) | Unique index on `upper(btrim(serial))` per tenant |
| One firmware operation in progress per device | Partial unique index on `device_operations` |
| One pending user command per unit (send disabled while pending, BR-C03) | Partial unique index on `control.commands` (restriction commands excluded) |
| Diagnostic run 1–15 minutes, reason required (FR-T10) | CHECKs on `control.diagnostic_runs` |
| One default alert policy per tenant; alert policy belongs to one customer | Partial unique index + CHECK on `monitoring.alert_policies` |
| One open alert per unit, policy rule and type | Partial unique index on `monitoring.alerts` |
| One pending slot proposal per job; one open offer per job; one active assignment per job | Partial unique indexes |
| A technician cannot be booked twice at the same time (FR-P03) | GiST exclusion constraint on `maintenance.assignments` |
| One draft report per job; one review per report version | Partial unique / unique indexes |
| Restriction executes at least 24 hours after notice (IR05) | CHECK on `restrictions.restrictions` |
| Payout net = gross − deductions | CHECK on `billing.payout_statements` |
| Webhook replay is harmless | Stripe event ID primary key on `billing.stripe_events` |
| Audit cannot be changed | `BEFORE UPDATE OR DELETE` trigger + `INSERT`/`SELECT`-only grants |

Rules that need data from more than one schema or from the clock (scope, validity periods, offline state, restriction minimum temperature) are enforced in Go (`domain/` and `authz`), not in SQL.

## 6. Telemetry, partitioning, and retention

| Table | Partitioning | Retention | Job |
|---|---|---|---|
| `monitoring.measurements` | Daily range on `observed_at` | 35 days | pg_partman: premake 7 days, drop older than 35 days |
| `monitoring.measurements_15m` | Monthly range on `bucket_start` | 3 years | pg_partman monthly |
| `monitoring.measurements_1h` | Yearly range on `bucket_start` | 7 years | pg_partman yearly |
| `audit.audit_log` | Monthly range on `occurred_at` | 7 years in the database; monthly export to S3 Object Lock | Export job, then detach and drop partitions older than 7 years |
| `platform.outbox` | none | Published rows deleted after 7 days | Daily cleanup |
| `platform.idempotency_keys` | none | 24 hours | Hourly cleanup by `expires_at` |
| `platform.processed_events` | none | 14 days (longer than the SQS retention) | Daily cleanup |
| `notify.notifications`, `deliveries` | none (index on time) | 2 years | Monthly cleanup |

The schema file creates only `DEFAULT` partitions so that it runs anywhere; production creates real partitions through pg_partman before the first write. Measurement writes use `COPY` (pgx `CopyFrom`) in batches; indexes are the primary key `(sensor_id, observed_at, sequence)`, `(unit_id, metric, observed_at DESC)` for the 24-hour chart (FR-T03), and a BRIN index on `observed_at`.

At the design capacity (20,000 units, about 120,000 measurements per minute) the hot table grows by roughly 170 million rows per day. If sustained ingest or storage exceeds Aurora's comfortable range, raw measurements move to a dedicated time-series store while aggregates stay here (backend architecture §13).

## 7. Tenant isolation and database roles

- Row-level security is enabled and forced on every business table with `tenant_id`; the policy compares `tenant_id` with `current_setting('app.tenant_id', true)`. The Go `TxManager` sets it with `set_config(…, true)` (transaction-local) at the start of every transaction, so a pooled connection never leaks a tenant.
- `platform.*` tables are not under RLS: the outbox relay and the scheduler read across tenants and then open a tenant transaction per item.
- Roles: the migration owner role (for example `ac_owner`, created with the cluster; owns objects), one role per business-domain service (IR194: `ac_svc_identity` → identity, notify; `ac_svc_equipment` → assets, devices, control, monitoring; `ac_svc_maintenance` → maintenance; `ac_svc_billing` → billing, restrictions; `ac_svc_energy` → energy; each also DML on platform and nothing on other domains' schemas; the audit log is identity's — `ac_svc_identity` alone has `INSERT`/`SELECT` on audit and the other services publish `AuditRecorded`, IR196), `ac_app` (all module schemas: tools and the all-domain development scheduler; the domain schedulers use the domain roles, IR195), `ac_worker` (workers: same rights), `ac_readonly` (analytics and support, read only). None has `BYPASSRLS`. Login uses IAM database authentication or Secrets Manager rotated passwords; locally `cmd/migrate` creates `ac_<domain>_login` for each service role.
- Scope (customer, property, unit, job assignment) is narrower than tenant and is applied by the queries generated for each operation, using the Principal's scopes; RLS is the safety net for tenant boundaries.

## 8. Concurrency and consistency

- Isolation level READ COMMITTED with optimistic versions on every aggregate; `SELECT … FOR UPDATE` on the aggregate root before changing child rows (job + offers / assignments, restriction + units, invoice + payments).
- Serialization or deadlock errors (40001, 40P01) are retried up to three times by the `TxManager`, then UNAVAILABLE.
- PostgreSQL errors map to contract codes: 23505 / 23P01 → CONFLICT, 23514 / 22P02 → VALIDATION, 23503 / 42501 → NOT_FOUND (never reveal other tenants), no rows on a scoped update → NOT_FOUND or CONFLICT after a version check.
- Every write inserts its outbox row(s) — including one `AuditRecorded` per audit entry, which identity stores in `audit.audit_log` (IR196) — in the same transaction (exactly-once business effect, at-least-once event and audit delivery). `maintenance.offers` and `maintenance.assignments` additionally publish `OfferAccessChanged` / `AssignmentAccessChanged` snapshots from row triggers (IR186); tables read by other services publish `RowChanged:<schema>.<table>` through `platform.capture_row` (IR188).

## 9. Migrations

- `cmd/migrate` (IR167, IR174) applies sequential files embedded from `service/api/internal/migrations` (golang-migrate naming and `schema_migrations` table, so the golang-migrate CLI can inspect or `force` the same database); [db/schema.sql](db/schema.sql) is `000001_init.up.sql`, and a test fails when the two differ until the first release freezes it. Applied migrations are never edited. `migrate up` refuses a database that has the schemas but no recorded version (`migrate force 1` records a psql-built schema) and stops on a dirty version left by a failed non-transactional migration.
- Expand → migrate → contract: add nullable columns or new tables first, deploy code that writes both, backfill in batches, then drop the old shape in a later release. CHECK changes for new enum values ship before the code that uses them.
- Large index builds use `CREATE INDEX CONCURRENTLY` in their own migration (no transaction).
- Go tests use their own database `ac_test` (`make testdb` in service/ rebuilds it with cmd/migrate; `AC_TEST_DATABASE_URL` / `AC_TEST_OWNER_DATABASE_URL` override it), never the development database `ac` that a running local API, worker or BFF uses (IR171).
- Each migration runs in CI against PostgreSQL 16 with the store tests; production runs it as a one-off ECS task before the service deploy (backend Go design §10).

## 11. Backup, restore, and environments

- Aurora PITR 35 days, daily snapshots copied to ap-southeast-1; restore drills quarterly (RPO 15 minutes, RTO 4 hours).
- Dev and staging use synthetic data only; production data is never copied to lower environments. Acceptance tests seed from fixture-contract.json.
- Personal data anonymisation (backend architecture §7) updates `identity.users` (status `anonymised`, e-mail replaced) and `identity.client_users`; audit rows keep IDs but never contact data (masked at write time).
