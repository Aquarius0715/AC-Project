# 施工業者 要件定義書

## 目的と前提

本書は[企業要件の英語原文（SRC-06）](../00-prepare/sources/company-requirements-original.txt)を一次資料として再整理した文書です。企業原文 → BIZ整理項目 → 本書のFR → 詳細設計・受入条件の順に追跡します。各機能の「企業要望」と「設計補完」を分け、画面項目・入力制約・状態遷移・優先度はフロントエンドの実装案として提示します。企業の詳細承認済みを意味しません。参考モックは外観設計の参考資料です。機能要件と受入条件は、企業原文の目的に制作方針・設計補完を加えて具体化します。

本書の対象は利用者がフロントエンドで確認・入力・操作できること。登録・請求・入金・機器操作・通知はモックで再現する。バックエンドの実処理・永続化・実認証は要件に含めない。

受託範囲の案件を受け付け、自社技術者・日程・作業品質を管理する。以下の具体業務はDEC-01に基づく提案。施工業者を独立役割とすること自体は企業原文にない制作方針で、原指示の記録は未収録（[確認状態](../00-prepare/sources/production-instructions.md)）。企業確認はOPEN-10で管理する。

必読: [PrepareDocument](../00-prepare/PrepareDocument.md)、[共通要件](common.md)。共通の認証、言語、音声、権限、通知、非機能要件をすべて適用する。

優先度P0は基盤・中核フロー、P1も1Aの完成対象。各行の受入条件は`AT-P番号`として検証する。企業の要望に対応する範囲と、具体的なUI・仮値の提案を区別する。

## 業務境界・依存関係

権限は[共通要件の権限マトリクス](common.md)を唯一の基準とする。画面表示の許可と変更操作の許可を分離し、サービス呼出し直前にも検証する。設備能力・作業期間・契約条件が変わった場合は古い画面の許可を使わない。

実機操作、外部通知、実決済、API認証は1B。1Aでは操作できるシミュレーションを用意し、成功だけでなく拒否・失敗・欠測を再現する。

- 全FR-P要件とFR-X/NFRの適用分を満たす。未実装を「対象外」に変更して完成扱いにしない。
- [詳細設計](../02-design/contractor.md)の画面・サービス・異常系と受入条件を対応させる。
- [検証計画](../04-agentic-sdlc/verification.md)に従い、AT-P全件と該当シナリオの証跡を残す。
- 不確定な業務判断はPrepareDocumentのOPEN台帳へ戻し、モックの仮定を報告する。

### FR-P01 受託ダッシュボード

- **企業要望の根拠**: SRC-06 BIZ-04, BIZ-12 — 顧客、社内/外部技術者、管理者/HQの視覚的なダッシュボード / 定期・事後・予防保全。RTO以外の一般保守にも利用。
- **設計補完の範囲**: 受託案件ダッシュボード。施工業者を独立させることはSRC-02の指定で、企業原文の独立役割ではありません。

- **利用開始条件**: 有効な施工業者Membershipがある。HQからのofferは受諾前でも案件概要を閲覧可能。
- **基本フロー**: 自社の受諾待ち・予定・進行・品質確認待ちを集計 → 状態を選んで案件一覧へ → 対象案件の窓口操作へ進む。
- **業務規則 BR-P01**: 受諾前は案件種別・地域・必要資格・日程候補までの最小情報。詳細設備値や顧客連絡情報は受諾後かつ期間内に限定する。
- **完了後の業務状態**: 閲覧による受諾は発生しない。KPIと一覧の対象集合を同じ検索条件で揃える。
- **境界条件・禁止事項**: 他社のofferを件数に含めない。委託期間終了で設備閲覧を閉じても、自社の受諾/辞退履歴の最小記録は確認できる。

### FR-P02 案件受諾・辞退

- **企業要望の根拠**: SRC-06 BIZ-12 — 定期・事後・予防保全。RTO以外の一般保守にも利用。
- **設計補完の範囲**: 受諾・辞退の手順。施工業者を独立させることはSRC-02の指定で、企業原文の独立役割ではありません。

- **利用開始条件**: 自社宛offered、offerExpiresAtより前、HQ未取消。
- **基本フロー**: 案件の最小情報・委託条件を確認 → 受諾または理由付き辞退 → HQと自社の状態表示を更新する。
- **業務規則 BR-P02**: 受諾は技術者割当や確定予約とは別。辞退時はrequestedへ戻し、辞退者・理由・offerIdを保持。再委託は新offerId。
- **完了後の業務状態**: 受諾でaccepted、必要な設備閲覧権を委託期間内だけ開く。辞退は詳細閲覧権を付与しない。
- **境界条件・禁止事項**: 締切一致時は辞退/受諾を拒否して再取得。受諾直前のHQ取消とのCONFLICT競合は自動上書きしない。

### FR-P03 日程と自社技術者割当

- **企業要望の根拠**: SRC-06 BIZ-12 — 定期・事後・予防保全。RTO以外の一般保守にも利用。
- **設計補完の範囲**: 自社担当割当と資格確認。施工業者を独立させることはSRC-02の指定で、企業原文の独立役割ではありません。

- **利用開始条件**: 受諾済み案件で、自社の割当管理権限を持つ。
- **基本フロー**: 希望枠と委託期間を確認 → 自社の有効技術者・資格・空き時間を検索 → 作業開始/終了を指定 → 割当確認 → 日程と担当を共有する。
- **業務規則 BR-P03**: 候補検索だけで権限判定を済ませず保存直前に所属・資格・期間を再照合。重複予定は警告し、同時間帯の確定重複は1Aでは保存拒否する。
- **完了後の業務状態**: 初回割当はAssignment作成、scheduledSlot確定、Job assigned。再割当は元のassigned/in_progressを維持し、旧割当を失効、元報告の著者を維持し変更理由を保存。
- **境界条件・禁止事項**: 他社/無資格/委託外期間の割当を拒否。作業中の再割当は理由なしでは保存できず、旧技術者は直ちに変更操作不可。

### FR-P04 対象設備と異常根拠閲覧

- **企業要望の根拠**: SRC-06 BIZ-12 — 定期・事後・予防保全。RTO以外の一般保守にも利用。
- **設計補完の範囲**: 対象設備・異常根拠の限定閲覧。施工業者を独立させることはSRC-02の指定で、企業原文の独立役割ではありません。

- **利用開始条件**: 受諾済みの有効委託に対象設備が含まれる。
- **基本フロー**: 案件から設備を開く → 場所・型番・保守範囲・通信状態・異常根拠を閲覧 → 案件へ戻る。

- **完了後の業務状態**: 業務更新なし。委託終了後は顧客設備のlive値を表示せず、自社案件履歴の最小参照へ戻す。
- **境界条件・禁止事項**: 画面を開いたまま期限を越えても次要求で拒否・キャッシュ破棄。監視値を見られることを制御権限と扱わない。

### FR-P05 報告品質確認・差戻し

- **企業要望の根拠**: SRC-06 BIZ-12 — 定期・事後・予防保全。RTO以外の一般保守にも利用。
- **設計補完の範囲**: 報告の品質確認・差戻し。施工業者を独立させることはSRC-02の指定で、企業原文の独立役割ではありません。

- **利用開始条件**: submittedの自社委託案件。レビュー担当は報告作成者と異なる。
- **基本フロー**: 提出版の点検・写真・測定・作業・次回対応を確認 → 受理または差戻し理由を記入 → 技術者/顧客/HQへ結果を共有する。
- **業務規則 BR-P05**: 受理は必須点検の記録と根拠が揃うこと。未点検/対象外の理由が妥当か確認。レビュー担当は技術者の原記録を編集しない。
- **完了後の業務状態**: 受理でcompleted、差戻しでrework_requested。レビュー履歴を報告版へ紐付ける。完了時もAlertを自動解消しない。
- **境界条件・禁止事項**: 自己承認、古いreportVersion、空の差戻し理由を拒否。差戻し後に古い受理操作が届いてもcompletedにしない。

### FR-P06 自社作業者・稼働閲覧

- **企業要望の根拠**: SRC-06 BIZ-12 — 定期・事後・予防保全。RTO以外の一般保守にも利用。
- **設計補完の範囲**: 自社作業者・資格・稼働の閲覧。施工業者を独立させることはSRC-02の指定で、企業原文の独立役割ではありません。

- **利用開始条件**: 自社の作業者一覧を読む権限。ユーザー作成権限は含まない。

- **境界条件・禁止事項**: 会社IDをURLから書換えて他社名簿を取得できない。失効した技術者を候補として選べない。

### FR-P07 案件連絡・履歴

- **企業要望の根拠**: SRC-06 BIZ-12, BIZ-20 — 定期・事後・予防保全。RTO以外の一般保守にも利用 / 小型・低価格で空調内に設置する機器、FW、取り外し・盗難への対策と通知。
- **設計補完の範囲**: 案件連絡・異常の共有。施工業者を独立させることはSRC-02の指定で、企業原文の独立役割ではありません。

- **利用開始条件**: 自社の案件に連絡・履歴閲覧権がある。
- **基本フロー**: 案件履歴を開く → 日程調整/品質連絡テンプレートを選ぶ → メモ・宛先役割を確認 → in-app記録と外部送信プレビューを作成する。
- **業務規則 BR-P07**: 実送信はしない。宛先は該当案件のHQ/担当技術者/顧客窓口のみ。内部品質メモは顧客非公開を初期値とする。
- **完了後の業務状態**: Noteを作者・公開範囲付きで保存。プレビュー操作だけではdeliveryStateをsentへ変更しない。
- **境界条件・禁止事項**: 任意メール宛先・他案件の宛先・顧客請求の転記を拒否。保存失敗でメモを保持する。

### FR-P08 委託・期間の境界

- **企業要望の根拠**: SRC-06 BIZ-12 — 定期・事後・予防保全。RTO以外の一般保守にも利用。
- **設計補完の範囲**: 委託先・担当期間に基づくアクセス制限。施工業者を独立させることはSRC-02の指定で、企業原文の独立役割ではありません。

- **利用開始条件**: 施工業者としてアクセスするすべてのrouteとRepository操作。
- **基本フロー**: Membership確認 → 自社offer/委託/期間を確認 → 最小データを返す → 操作直前に再確認する。
- **業務規則 BR-P08**: live設備は受諾済みかつ期間内だけ。失効後の履歴は自社受諾/辞退/作業の最小記録で、過去アクセスを理由に顧客データ全件を返さない。
- **完了後の業務状態**: 拒否では業務変更0件。監査には秘密を含めず拒否理由コードを記録。session切替で旧Queryを破棄。
- **境界条件・禁止事項**: 他社jobId、期限一致、未受諾の設備、請求変更、制限操作をそれぞれ拒否し、禁止対象のデータを応答へ含めない。

|---|---|---|
| AT-P08-N | contractor-a session。When: 全route・Repository操作 | ①最小projection ②操作直前に再確認 ③拒否時の業務変更0件 |
| AT-P08-E | ①他社jobId ②now=validUntil ③未受諾設備 ④invoices.create ⑤restrictions.schedule | 各FORBIDDEN／NOT_FOUND、監査に理由コード、応答に禁止データなし |
| AT-P08-B | ①未受諾 ②期間内受諾済み ③期間失効 | ①JobOfferSummary ②JobDetail＋live設備 ③JobHistorySnapshotのみ |
