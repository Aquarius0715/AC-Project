# 共通要件定義書

上位: [PrepareDocument](../00-prepare/PrepareDocument.md)。本書は4役割の要件定義書と組み合わせて読む。出所は企業原文・制作方針・設計補完に区分します。

本書は[企業要件の英語原文（SRC-06）](../00-prepare/sources/company-requirements-original.txt)を一次資料として再整理した文書です。企業原文 → BIZ整理項目 → 本書のFR → 詳細設計・受入条件の順に追跡します。各機能の「企業要望」と「設計補完」を分け、画面項目・入力制約・状態遷移・優先度はフロントエンドの実装案として提示します。企業の詳細承認済みを意味しません。参考モックは外観設計の参考資料です。機能要件と受入条件は、企業原文の目的に制作方針・設計補完を加えて具体化します。

## 権限マトリクス

「対象内」はtenantId一致に加え、顧客所属／委託案件／担当・有効期間が一致すること。HQでも全テナントを無制限に見ない。

| 操作 | クライアント | 施工業者 | 技術者（社内/外部） | HQ |
|---|---|---|---|---|
| 設備・場所の閲覧 | 利用範囲 | 受託案件の必要情報 | 社内:担当範囲 / 外部:割当設備・期間 | 管理範囲 |
| 物件・場所の作成編集 | 自組織内 | 不可 | 不可 | 管理範囲 |
| 通常空調操作 | 対象内・能力内 | 原則不可 | 診断能力権限＋対象・期間内 | control.execute権限 |
| 保守依頼 | 自設備 | 受託案件の調整 | 担当案件の対応 | 管理範囲で作成・割当 |
| 業者受諾・自社割当 | 不可 | 受託案件、自社かつ資格・期間内 | 不可 | 委託・社内割当 |
| 点検・作業報告 | 結果閲覧 | 閲覧・品質確認・差戻し | 担当案件で作成 | 閲覧・品質確認 |
| 請求閲覧・支払いデモ | 自契約 | 不可 | 不可 | billing.manage権限で管理 |
| 制限・猶予・解除 | 理由閲覧 | 不可 | 不可 | restriction.manage、overrideは別権限 |
| IoT登録・校正・FW | 状態閲覧 | 受託設備の状態閲覧 | device.maintain＋担当内 | device.manage権限 |
| MRV・監査 | 自分向け推定値・履歴 | 案件の必要履歴のみ | 担当の操作履歴 | mrv.manage / audit.read権限 |
| ユーザー・ロール変更 | 不可 | 自社の割当候補閲覧のみ | 不可 | identity.manage権限 |

閲覧不可の資源は存在の詳細を漏らさない。操作不可の理由は、閲覧自体が許されている場合にのみ表示。施工業者に技術者の操作を自動付与しない。業務責任者が複数の役割を持つ場合も明示したMembershipを切り替える。

## 業務不変条件

- 室温と設定温度、要求値と機器確認値は別。完了判定はデモでも応答イベントが必要。
- 作業完了は異常解消ではない。解消には再測定または記録付き確認操作が必要。
- 支払い操作は入金確認ではない。制限解除は入金後の解除要求と機器応答を経る。
- 制限、診断、FW更新、音声変更は能力・権限・スコープの検証を共通化する。
- 室内CO₂、粉じん、電力排出量の欠測は0に置換しない。省エネ率を保証せず、排出量をクレジットとして発行しない。
- デモに用いるしきい値や契約ルールは仮値であり、医学的・法的・電気施工上の判断を規定しない。

## 共通機能の具体的な業務条件（0.6.0）

### FR-X01 セッション・言語

- **企業要望の根拠**: SRC-06 BIZ-01, BIZ-02 — サインイン、サインアウト、パスワード再設定 / 任意の言語を選べる表示。
- **設計補完の範囲**: 4役割デモ・初期en/ja・再設定文言。

デモログインは架空アカウント一覧から選択し、4役割と社内/外部技術者のMembershipへ入る。本人の実メール・パスワードを入力する必要はない。未ログインで保護routeを開いた場合はログインへ移動し、戻り先は許可された相対routeだけ保持する。サインアウト・役割切替で旧画面・Query・画像preview・権限依存draftを破棄する。

パスワード再設定のデモはメール形式だけ検証し、登録有無によらず同じ完了文言と送信プレビューを返す。言語切替は英語/日本語の表示に反映し、保存データのUTC・単位・IDを変更しない。AT-X01では`demoSession.signIn/signOut/switchMembership`と`auth.previewPasswordReset`、`preferences.update`（locale）を対象に、保護route直打ち、ログアウト後の戻る、役割切替中の旧応答、未登録形式のデモメールでも存在を漏らさないことを検証する。

### FR-X02 音声・問い合わせ

- **企業要望の根拠**: SRC-06 BIZ-03 — 音声AIで応答できること。
- **設計補完の範囲**: 音声応答を温度照会・機器操作・問い合わせへ展開する案、音声デモとテキスト代替・変更確認。音声による機器変更自体は原文に明記されていない。

対応intentは温度照会・設定温度変更・問い合わせ。部屋名が複数一致する場合は対象候補の選択が必要で、推測して実行しない。認識できないintentは「操作できません」とテキスト入力へ戻す。音声の変更要求は画面で対象・旧値・新値を提示してからCommandへ渡す。確認前は業務変更0件。

AT-X02では同名の部屋2件、権限外の部屋、非対応温度、マイク拒否、確認取消を検証する。位置/マイク同意の取消は現在の意図を破棄し、過去の機器応答を取り消したとは扱わない。実音声サービスは接続しない。

### FR-X03 状態と品質

- **企業要望の根拠**: SRC-06 BIZ-09, BIZ-18 — 赤・オレンジ・緑のシグナルと通知 / CO₂濃度、粉じん、湿度、アレルゲン等の把握と清掃・換気案内。
- **設計補完の範囲**: 色の意味・単位・品質・非色表現。

重要度・接続・運転・業務進捗・データ品質は別々の軸として表示する。接続offlineでも最後の電源状態はlast-knownとして残せるが、現在稼働中と断定しない。測定欠測を0へ変換せず、値と更新時刻・品質を対にする。AT-X03では同じ設備で「通信断＋過去の電源ON＋未解消warning」を同時に表示できること、ppmとkgCO₂eが別metricであることを確認する。

### FR-X04 スコープと操作権限

- **企業要望の根拠**: SRC-06 BIZ-04 — 顧客、社内/外部技術者、管理者/HQの視覚的なダッシュボード。
- **設計補完の範囲**: 役割・担当・期間・能力の表示制限。

許可条件は有効session AND tenant一致 AND role/permission許可 AND 資源scope一致 AND 有効期間内 AND 現状態/能力条件を満たすこと。閲覧projectionもこの条件で決める。顧客/業者/外部技術者はそれぞれ違う境界で判定する。権限確認をメニュー表示時だけにしない。

AT-X04では別テナント、同テナント別顧客、別業者、無資格技術者、期限一致、権限変更後の古い画面、同一人のMembership切替による自己承認を個別に否定検証する。これはフロントエンドのデモ表示・操作制御の検証で、本番認可の設計・実装は対象外。

### FR-X05 デモと共有データ

- **企業要望の根拠**: SRC-06 BIZ-05 — 分離型エアコンを先行し、最初にクリック可能なUI/UX、その後に全体ソリューション。
- **設計補完の範囲**: 共有モック・リセット・実処理の区別。

seedは固定し、同一タブで4役割が同じIDの業務状態を読む。role切替は業務データをリセットせず、リロード/明示リセットは初期値へ戻す。リセット前の遅延イベントが新しいseedへ入り込まない。状態操作パネルは業務画面と区別し常時デモ表記。AT-X05では`demo.reset`・`demo.trigger`・`demoSession.switchMembership`を対象に、seed再現、役割間整合、旧遅延イベント破棄、決済/通知/IoT/取引への実接続0件を確認する。

### FR-X06 能力と契約種別

- **企業要望の根拠**: SRC-06 BIZ-05, BIZ-06, BIZ-12, BIZ-19 — 分離型エアコンを先行し、最初にクリック可能なUI/UX、その後に全体ソリューション / HVACを第2段階とし、メーカーや分離型・中央空調・カセット型等へ対応拡大 / 定期・事後・予防保全。RTO以外の一般保守にも利用 / CO₂上昇時に外気導入等を行い、空気環境を改善。
- **設計補完の範囲**: 機種能力と画面有効判定。

Capabilityは型番版に紐付け、未確認は対応として扱わない。一般保守設備はRTO請求がなくても操作可能。制限可否はRTOという名前だけでなく契約のrestrictionEligibleを確認する。AT-X06では温度非対応・モード候補差・送風のみ・一般保守・制限不可RTOの5種類を用意する。

### FR-X07 通知・監査

- **企業要望の根拠**: SRC-06 BIZ-08, BIZ-20, BIZ-22 — 異常を事前または発生時に把握し、リアルタイム通知する / 小型・低価格で空調内に設置する機器、FW、取り外し・盗難への対策と通知 / WhatsApp/メールとカード決済・支払い手順への導線。
- **設計補完の範囲**: 既読・関連画面・操作履歴。

通知先はイベントと現在の業務scopeから選ぶ。顧客向けには品質受理済み報告だけ公開し、内部差戻しメモを表示しない。監査は当時の主体・役割・対象・理由・結果・版・相関IDを保持する。AT-X07では既読後も異常が残ること、報告受理前後の公開差分、サインアウト後も過去のactorが変わらないことを確認する。

具体的な受渡しは[フロントエンド入出力契約](../02-design/implementation-contracts.md)へ。非機能要件は数値目標と測定環境を併記して判定し、ライブラリの導入だけで達成扱いにしない。
