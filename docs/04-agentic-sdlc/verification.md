# 検証計画・受入シナリオ

本書は将来の実装に対する試験計画。今回アプリは実装しておらず、以下の試験はすべて未実行。[追跡表](../00-prepare/traceability.csv)の64要件、AT-C/P/T/A/X、AT-NFRを個別に検証し、S01〜S08で役割横断の整合性を追加確認する。横断シナリオだけで全要件を検証済みにしない。

本版では4役割49要件にそれぞれAT-番号-N（正常）、-E（異常）、-B（業務条件）を定義し、147ケースへ分解した。原文補完のAT-*-SRC 10件、共通7件・NFR8件と合わせた要件の葉ケースは172件（役割別147＋原文補完10＋共通7＋非機能8）。UI専用ケースと役割横断Sシナリオはこの件数とは別に検証する。各ケースに複数条件がある場合、実行時にはその条件ごとのsubcaseを記録する。全subcaseを満たすまで親ATをpassにしない。

## 1. テスト階層・完了の証跡

| 階層 | 主な検証 | 証跡 |
|---|---|---|
| Unit | policyのテナント/期間/能力、状態遷移、金額・排出量計算、schema境界 | ケース名・結果・対象関数 |
| Component | 入力検証、disabled理由、要求/確認値、欠測、Dialogのフォーカス | RTL等の利用者操作テスト結果 |
| Contract | フロントサービスの入出力・合成エラー・表示範囲・重複操作・version。対象はmockのみ | adapter名、request/responseのマスク済み記録 |
| E2E | 同一タブで4役割を切替するS01〜S08、ディープリンクと再読込 | 実装版、ブラウザ、動画/trace/スクリーンショット |
| 手動・自動a11y | キーボード、スクリーンリーダー、コントラスト、360/768/1280、拡大200%、日英 | 環境と実際の操作・結果。自動検査だけで適合を宣言しない |

実装時にpackage scriptsを定義してから型/lint/build/testの実コマンドを記録する。まだ存在しないコマンドの成功を記入しない。受入には全P0/P1要件の検証、P0/P1欠陥ゼロ、残りの欠陥・未決の明示が必要。失敗を対象外扱いして除外しない。

## 3. S01 部屋から空調操作

前提: customer-a、onlineの対応設備、未制限。操作: 自組織に自宅/オフィスの物件・階・部屋を作成/編集し、他組織親IDと循環を拒否できることを確認。自宅→階→部屋→設備を開き、室温28°C・設定26°Cを確認し設定24°Cを要求する。requested→sent→acknowledgedイベントを順に発火する。

期待: 応答前は確認済み設定26°Cを保持し、要求24°Cを別表示。応答後のみ設定24°C、室温28°Cは変えない。履歴に同一commandId。失敗・期限切れでは成功通知なし。offlineや非対応モードは理由付き不可。一般保守設備でも同じ操作が可能。

追加: 重複クリック、同じ冪等キー、古い応答、期限後応答、権限変更中の操作、役割切替中の遅いレスポンスを検証する。異なる顧客の直接URL/Repository呼出しを拒否する。

## 4. S02 異常から保守完了

前提: unit-online-rtoにフィルター点検推奨のalert。操作: 顧客が設備から保守依頼→HQが社内技術者割当→技術者が根拠と室内/室外/電気の点検・写真・測定・部品・次回対応を記録→提出→HQが品質確認。

期待: 同一jobIdがassigned→in_progress→submitted→completed。顧客に結果、HQに完了。アラートはopen/acknowledgedのまま。再測定または理由付き解消操作後に初めてresolved。

追加: 必須欠落の提出拒否、差戻し→改版→再提出、二重提出、保存失敗で入力保持、取消済み/期間失効案件の開始拒否。外注経路はS08で検証する。

## 5. S03 支払い・運転制限

前提: 期限超過invoice、制限可契約、onlineとofflineの対象設備、権限付きHQ。操作: 予告作成→顧客が理由/期限/解除条件と通知プレビュー確認→HQが期限前実行を試す→デモ時計を進めて適用要求→一部設備のみ応答→顧客が模擬決済→入金確認→解除要求→設備応答。

期待: 期限前は拒否、適用/解除は全件の機器反映まで完了にしない。カード実入力/外部送信なし。決済処理中は未入金、確認後paid。offlineは保留。監査に主体、理由、時刻、対象、相関IDが残る。

追加: 猶予、例外、事前取消、要求後取消→解除、手動解除、権限不足、一般保守契約、二重入金確認、CONFLICT競合、解除要求後の遅い適用応答、失敗再試行。手動解除してもInvoiceをpaidへ改変しない。

## 6. S04 空気環境・換気

前提: CO₂濃度上昇、換気設備なし/ありの2設備。操作: 合成センサー値を変更し、顧客案内とHQのしきい値・通知方針を確認する。換気能力ありだけ模擬要求する。

期待: ppmとしきい値のデモ表示。設備なしは換気案内のみ、送風を換気と呼ばない。欠測は不明、0や正常にしない。高CO₂表示を医学的な保証としない。

追加: 自動運転の条件欠測、HQ方針との優先順位、制限中の発火拒否、CO₂とkgCO₂eの単位混同がないこと。

## 7. S05 電力・排出量・MRV

前提: 上記100/80kWhの仮データ。操作: 顧客とHQで期間・設備・基準を合わせて比較→MRVプレビュー→模擬オフセット申込・償却記録。

期待: 算定値がfixtureの期待値に一致し、条件・係数版・品質・推定/デモを表示。欠測時はcoverage低下、基準0は率なし、実績120なら負削減。MRVは外部検証済み表示なし、オフセットは実証明や実取引を生まない。

追加: 期間逆転・異なる算定境界・係数欠落・期待サンプル0の拒否/算定不可、他顧客の分析値を集計しない。

## 8. S06 IoTライフサイクル・異常

前提: 未登録device、校正可能sensor、対応FW候補。操作: 技術者が登録→設備紐付け→接続確認→校正履歴→FW成功/失敗→通信断・電源断・取り外し専用イベント→復旧。

期待: 重複serial拒否、対象外設備への紐付け拒否。失敗FWは版不変、進行中は制御不可。通信断だけで盗難と表示しない。HQ/技術者に同じ検知・復旧時刻。復旧だけで取り外し事象を消さない。

追加: 校正値の単位不整合、未対応FW、期間切れ、リセット後に旧非同期更新が復活しない。

## 9. S07 言語・音声・自動運転

前提: en/ja辞書、音声はシミュレーション。操作: 言語変更→主要画面・通知・AI応答切替→音声デモで温度照会→設定変更の確認→マイク拒否/未対応→テキストで続行。

期待: 対象と設定値を復唱して確認、通常Commandと同じ権限・能力を適用。拒否でもテキストで完遂。実マイクを使っていないことを表示。新規通知と既存通知の文言も選択言語で表示。

追加: 曜日・時間帯・帰宅前の冷房ルール作成/編集/停止と次回時刻、在室/天候/生活パターン/位置イベントの模擬発火。位置同意の拒否・取消で位置依存ルール停止。タイムゾーン変更・日跨ぎ・期限境界で時刻を検証。

## 10. S08 施工業者と外部技術者

前提: 顧客依頼、HQ、2業者、各社技術者、有効委託期間。操作: HQが業者aへoffer→業者aが辞退→HQが再委託→受諾→自社技術者割当→技術者が作業提出→業者が差戻し→再提出→品質受理→顧客・HQの完了確認。

期待: offered/accepted/assigned/submitted/rework_requested/completedが同じjobIdで整合。自社チーム候補だけ表示、品質確認者と作業者は別、連絡はプレビュー。業者が請求や制限を操作できない。

追加: 他社/無資格/期間外候補の割当拒否。委託失効後は開いている画面からの操作も拒否。再割当で旧担当のアクセスを失効。URL直打ち・Repository直呼出しで他案件/顧客情報を漏らさない。

## 14. 詳細化で追加した境界試験

- 予定: from/toと日跨ぎ、曜日0件、開始=終了、夏時間の不在/曖昧時刻、確定日程重複、委託期間の境界。
- 権限: 未受諾offerの最小projection、受諾後の設備閲覧、失効後の最小履歴、同一userIdのMembership切替による自己承認拒否。
- 保存: Unicode code pointでの文字数、5MiB画像境界、MIMEと内容の一致、draft/submitの必須条件差、CONFLICTで未保存入力を保持。
- 非同期: Command30秒、stale120秒、見積15分、予告24時間はデモ値として境界試験。制限解除の意思を保持し、未確定の適用要求と解除を競合送信しない。
- 会計・環境: 全額入金の額/通貨/参照一致、基準と実績の同一境界、MRVの版固定、購入確認前の償却拒否・二重償却拒否。
- 操作カタログ: 全論理操作の入出力とrole DDを照合。全操作がモックまたはローカル表示設定で完結し、外部接続を行わない。
